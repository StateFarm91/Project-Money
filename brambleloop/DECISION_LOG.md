| B-011 | 2026-09-17 | Opportunity scoring is a weighted sum of six named components, computed in code. Every score decomposes into demand, competition headroom, verifiability, seasonal fit, margin and whitespace, and the weights are one editable dict. | Yes — weights are data |

Using the event's generic make time would give a stocking and a throw the same deadline, and they are six weeks apart. | B-015 | 2026-09-17 | Competitor profiles carry an observation date and a URL, and are asserted on in tests. | Market evidence rots silently. An undated price band read as current a year later is worse than no data, because it looks like data. | No |
| B-016 | 2026-09-17 | Stitch taxonomy carries `height` (turning-chain units) and `row_height` (physical) as separate fields. | They were one field. A dc turns with three chains and is about twice the height of a sc; conflating them overstated a blanket's finished length by half. Finished length is a size claim on a listing, so this was a refund waiting to be printed, not a rounding issue. | No |
| B-017 | 2026-09-17 | Yarn constants are anchored on a checkable reference, and the anchor is written down next to them. | The first table was set by feel and came out at less than half of a defensible figure — a throw would have been advertised as needing 190 m. An estimate is allowed to be wrong by its stated tolerance; being wrong by a factor of two is not an estimate. Still uncalibrated at +/-20% until physical tests replace it. | Yes, on evidence |
| B-018 | 2026-09-17 | The flagship's pattern is generated from a motif grid, and each row is emitted as a repeat rather than flattened. | Flattening twelve repeats of a twelve-stitch motif produced a row instruction eleven lines long: physically unusable, and the kind of thing that makes a maker lose their place and blame the pattern. The repeat form is both what a human follows and what the compiler checks for divisibility, so readable and verifiable are the same form. | Yes |
| B-019 | 2026-09-17 | Large charts are published as one detected repeat plus a placement note, never as the whole piece. | A 144 x 120 chart on one page gives each stitch about a pixel. The repeat is *computed* from the fabric rather than asserted in copy, so the chart cannot claim a repeat the pattern does not have. | Yes |
| B-020 | 2026-09-17 | Web, worker and scheduler run in one container for now. | Railway bills by resources consumed and the company has no revenue; three always-on services cost roughly three times one. | B-021 | 2026-09-17 | With `BRAMBLELOOP_REQUIRE_POSTGRES=1` the app refuses to start rather than fall back to SQLite. | A container that silently falls back to a file on ephemeral disk passes every health check, renders the dashboard, and destroys every job, audit record and release certificate on its next restart. Failing to start is enormously preferable to a company whose memory quietly resets. | No |
| B-022 | 2026-09-17 | Artifact bytes are stored on local disk; artifact hashes are stored in Postgres. | No object storage is provisioned. The split means the system can always prove the PDF it is about to ship is the one that was certified, and when a file is gone it knows it is gone instead of serving a different one. Every run audits `assets.storage_not_durable` rather than implying durability it does not have. | Yes, swap in S3 |
| B-023 | 2026-09-17 | Prompts are immutable, content-hashed and referenced as `name@version`. | A prompt is a dependency, not a string. If it can be edited in place then two runs of the same job are not comparable, a regression cannot be attributed, and the audit trail records a call to something that no longer exists. Editing means publishing a new version; the old text stays so last month's output can still be explained. | No |
| B-024 | 2026-09-17 | No registered prompt may ask a model for pattern content, and this is enforced by a test. | Section 2 is absolute and a standing constraint is worth nothing if it lives only in a docstring. The prompt set is deliberately narrow: naming, readability polish that may not change a fact, and review mining. Everything load-bearing stays deterministic. | No |
| B-025 | 2026-09-17 | `ModelGateway.require_deterministic()` raises rather than returning a model verdict. | Section 27 says deterministic validation wins even if every LLM disagrees. Making it a method rather than a comment means a future caller reaching for a model opinion on pattern correctness gets an exception instead of a code review that may not happen. | No |
| B-026 | 2026-09-17 | The gateway ships with a deterministic `EchoProvider` and reports zero real providers. | No API key exists in this environment. Echo mocks the transport — pinning, parsing, cost, failover, circuit breaking — never judgement, which eval fixtures test instead. `available_providers()` returning an empty list is the truthful answer, and the dashboard shows it. | Yes, when a key exists |
| B-027 | 2026-09-17 | Agent permissions and ceilings are declarative: `seed_defaults` reconciles them on every boot. | Insert-if-absent meant a permission fixed in code never reached a database that already had the agent. Production proved it: the heartbeat fix deployed and the heartbeat kept failing. A permission that lives in code and cannot reach the database is not a permission, it is a comment. Runtime state such as `enabled` is left alone. | No |
| B-028 | 2026-09-17 | The container becomes healthy before it takes on load (`BRAMBLELOOP_RUNNER_START_DELAY`). | Two deployments were marked failed by the platform while working perfectly: the embedded worker began a full planning cycle at startup, and rendering eleven products' PDFs is CPU-bound work holding the GIL, which starved the health endpoint past the timeout. Serving first and working second is how a container is supposed to start. | Yes |
| B-029 | 2026-09-17 | Dead letters can be re-driven, but a closed capability gate can never be. | A dead letter from a fixed defect is work the company still owes, and leaving it red for a day teaches an operator to ignore the signal. Re-driving a shadow-mode publish refusal, by contrast, is an operator repeatedly asking a closed gate to open. A permission denial IS re-drivable: it reads like a refusal and is usually a misconfiguration, and the worker re-authorises on dispatch so a still-missing permission simply fails again. | Yes |
| B-030 | 2026-09-17 | `/api/verify` evaluates the standing safety assertions against live state and returns 503 if any fails. | "Railway says deployed" is not "the company is alive and behaving". The questions an absent owner actually has — is it running, is its memory durable, has anything escaped shadow mode, are the money guards on — are now answerable in one request, with the evidence for each check attached so a green result can be argued with. | No |
| B-031 | 2026-09-17 | The brand is data — palette, type, crop rules, naming grammar, character bible — not taste. | Consistency maintained by judgement alone does not survive a system producing assets unattended for months. `check_grid_coherence` can say whether the storefront still reads as one shop without anyone looking at it. | Yes |
| B-032 | 2026-09-17 | The brand model is refused for product-first categories, refused any real-person likeness, and can never be the hero. | Section 6 says product-first imagery is stronger for blankets and decor, and a model holding a blanket hides the pattern being sold. A likeness of a real person is refused however the request is phrased. An AI lifestyle concept as hero would be a picture of a thing nobody has made presented as evidence the thing exists. | No |
| B-033 | 2026-09-17 | Listing imagery is part of the release: rendered from the twin, class-declared, Asset Truth-checked, and blocking. | Imagery assembled after certification is imagery nothing verified. Rendering every frame from the same twin as the PDF means no frame can assert something the pattern does not produce, and a listing whose imagery misrepresents the pattern now stops the chain before pricing. | No |
| B-034 | 2026-09-17 | Search coverage is scored against *reachable* queries, not the biggest ones. | A shop with no history is not placing for "crochet blanket pattern", and scoring against it would tell the system to spend all thirteen tag slots on queries it will never appear for. Technique tags are gated on techniques the pattern actually uses: ranking for something we are not is a bounce, not a win. | Yes |
| B-035 | 2026-09-17 | Pricing optimises expected contribution per visitor, never gross revenue or lowest price. | A cheaper pattern converts better and can still earn less per visitor; a dearer one can earn more in total while killing the review accumulation a new shop depends on. Every figure is net of Etsy's real fee stack, because a decision made on gross is made on a number that never reaches the bank. | Yes |
| B-036 | 2026-09-17 | A price experiment's stopping rule is fixed before it starts, and a sub-8% price difference is refused at design time. | A test whose stopping rule is decided while looking at the results is a way of confirming what the operator already believed. At the sample sizes a new shop can reach, a 3% price difference is unmeasurable. | No |
| B-037 | 2026-09-17 | Thumbnail composition is checked now; hero ranking waits for real impressions and refuses without them. | Section 7 asks for both. The compositional half works today because a hero can be downscaled to Etsy's real grid size and measured. The evidence half cannot: inventing plausible CTRs to make a ranking function return something is the fabricated engagement section 8 forbids, applied to ourselves. | Yes, when data exists |
| B-038 | 2026-09-17 | Support triage puts escalation first in the routing table, and every reply is recorded as unsent. | A message containing both "chargeback" and "yarn" is a dispute; ordering is what stops a legal matter reaching the materials desk. And "we could not have sent it" is a weaker guarantee than "we recorded that we did not". | No |
| B-039 | 2026-09-17 | The portfolio classifier returns NO_EVIDENCE rather than a diagnosis for a SKU nobody has seen. | Every SKU has zero impressions. A classifier that read that as CONVERSION_PROBLEM would retire a catalogue that has simply never been shown to anyone — the most expensive mistake available to this component. | No |
| B-040 | 2026-09-17 | Confidence is tracked as seven separate dimensions with deliberately no overall score. | An average is more confident than the guess and less confident than the proof. Arithmetic confidence is near-total and yardage confidence is 0.45; averaging them would let a listing imply the yarn figure is as solid as the stitch counts. Physical confidence starts at zero and no amount of computation moves it. | No |
| B-041 | 2026-09-17 | Regression fixtures store the defective pattern, not the fix, and a clean pattern cannot become one. | A suite made of fixed patterns proves only that the fixed patterns are still fixed. A fixture that provokes no finding asserts nothing, and a suite full of those reports green while testing nothing. | No |
| B-042 | 2026-09-17 | Products are generated from a validated motif library; a width the motif cannot tile is refused. | Engineering twelve products by hand is twelve chances to slip. A truncated motif compiles perfectly and leaves half a fir tree down one side — a defect no arithmetic will ever catch, so the builder refuses rather than fudges. | Yes |
| B-043 | 2026-09-17 | A bundle has no pattern of its own and is assembled from its members' certified releases. | The pipeline had been certifying a "Nordic Forest Collection Bundle" whose PDF was a twelve-row striped panel: a product sold as three patterns and delivered as one invented swatch. A collection now lists only members that actually shipped, and waits when fewer than two have. | No |
| B-044 | 2026-09-17 | The books are built while every figure is zero, and the tax reserve is never counted as ours. | Accounting that first appears alongside the first sale is accounting nobody has checked; accounting built while the answer is obviously zero can be checked against an answer everyone knows. GST/HST is money held for a government, and counting it as revenue is how a small business discovers a liability it has already spent. | No |
| B-045 | 2026-09-17 | The CA$100K trajectory refuses to produce a run rate or a projection from zero orders. | It is the number most likely to be quoted back as though it were a forecast. With no orders there is no run rate; what the function returns instead is arithmetic on the target, labelled as arithmetic. | No |
| B-046 | 2026-09-17 | The CFO/Skeptic reports concerns even when nothing is wrong. | A reviewer who only speaks up during a crisis is a reviewer nobody has calibrated. It blocks on infrastructure above the owner's ceiling and on advertising with no attributable orders, and notes the burn and the tax reserve every time. | Yes |
| B-047 | 2026-09-17 | Paid-media guard rails are built now, while no campaign exists and no money can be spent. | Advertising is the one part of this system that can lose money quickly and silently. | B-048 | 2026-09-17 | Broken tracking pauses a campaign before any budget question is asked. | A campaign running with broken attribution is not one that might be losing money; it is one nobody can tell is losing money, and a budget cap does not protect against being blind. | No |
| B-049 | 2026-09-17 | Every acceptance-gate line has its own named test. | "Gate B passes" was previously inferred from a scattering of component tests. | B-050 | 2026-09-17 | Difficulty claims are checked in both directions. | The rule only caught "beginner" on a Class C pattern, which left the gate line "unsupported difficulty claims are blocked" half true. Overstating difficulty is just as unsupported as understating it, and it turns away the buyer the product was designed for. | Yes |
| B-051 | 2026-09-17 | Every idempotency key after certification carries a chain version. | Production proved the need: fifteen products were certified before listing imagery, search coverage and the content ecosystem existed, and the next cycle collapsed every downstream job against keys that were already taken — reporting success and producing nothing. Certification is correctly once per version; everything after it is different work when the code that does it changes. | Yes |
| B-052 | 2026-09-17 | `chain.rebuild` runs hourly and restarts certified releases that have no current listing. | Bumping the chain version makes the keys free; something still has to notice. A certified product with no listing is a product that cannot be sold, which is worth checking for on a cadence rather than only after a deploy. | Yes |
| B-053 | 2026-09-17 | A listing-copy change bumps the chain version so it reaches products already shipped. | The first title generator produced "Pet Snuggle Mat \| ... \| Pet Pet \| ..." and it went to production. A stuttering title is the clearest possible signal that nobody read the listing before it went up, and fixing the generator without bumping the chain would have left the stutter on every shipped product. | Yes |
| B-054 | 2026-09-17 | `create_all` is followed by an additive schema migration that adds missing columns and their indexes. | `create_all` does not touch a table that already exists, so a column added in code never reaches a deployed database. This is the third instance of one problem — code changed, the deployed database did not — after the agent permission and the release chain. Additive only: it will not drop, narrow, rename or backfill, and it refuses a NOT NULL column with no default rather than guessing. | No |
| B-055 | 2026-09-17 | Listings record the chain version that produced them, and the rebuild restarts stale ones, not only missing ones. | The first rebuild asked whether a listing *existed*. A stale listing exists, so a copy fix reached nothing and every shipped product kept a stuttering title through two deploys. Staleness has to be visible to be actionable. | No |
| B-056 | 2026-09-17 | An added column is backfilled with the model's literal default. | Without it a fresh database has the column NOT NULL with a value and a migrated one has it NULL, so the same code reads two different shapes — and the comparison deciding whether a row is stale silently compares against None. Only literal defaults are backfilled; a callable default is per-row logic this module has no business guessing. | No |
| B-057 | 2026-09-17 | Row-level repeats are derived from the compiled rows, never declared in the CIR. | A declared repeat is a second statement of the same fact, and two statements can disagree while both stay internally consistent — no arithmetic would catch it, because both halves add up. `detect_cycle` computes the cycle from the rows the compiler already validated, so there is no field to get wrong and nothing to keep in sync. The cost is that an intended repeat the designer wants stated but the rows do not support cannot be expressed; that is the right refusal. | No |
| B-058 | 2026-09-17 | The reverse compiler parses and expands the repeat instruction itself, from the customer text alone. | The obvious shortcut is for the writer to hand the reader its expansion. Then the two are no longer independent and the whole validation chain checks its own work (B-005). So the reader has its own regex and its own expansion, and it refuses a repeat that points at rows the text never printed. A reader that ignored the instruction instead would report every collapsed pattern as ninety rows short, which is worse than not supporting repeats at all. | No |
| B-059 | 2026-09-17 | A piece worked in the round is measured as a surface of revolution, not as flat fabric. | The flat model reads stitches-around as a width. Thirty stitches at 20 sts/10cm is 15 cm of *circumference*, which is a piece under 5 cm across, so a listing built on it advertises a three-inch bauble as a six-inch one. One relationship covers every case -- row height squared equals radius change squared plus axial rise squared -- and it also explains why "+6 sc per round" makes a flat circle, and tells us when the fabric must gather. | Yes |
| B-060 | 2026-09-17 | The twin refuses a width and a height for a closed shaped piece, and states a circumference instead. | Rounds 2-5 of every amigurumi grow at almost exactly one row height, which is geometrically the flat case, so the surface model sincerely reports a hemisphere as a half-centimetre pancake. It is not wrong about the fabric; the ball is made by the stuffing and the maker's tension, and neither is in the gauge. A circumference is arithmetic and a height is a physical measurement, so we give the first and refuse the second (section 3). | No |
| B-061 | 2026-09-17 | A product's own name is checked against the shape the pattern makes. | "Market Basket Trio" was a single flat rectangle whose designer note admitted it was "the side panel, seamed into the basket", with no seaming instruction in the document; "Hexagon Coaster Set" was a rectangle. Both were certified and drafted into listings. The check is deliberately narrow -- a three-dimensional noun, or a shape word attached to the object -- because mosaic work legitimately depicts stars and hearts *on* rectangles and over-flagging that would block real products. | Yes |
| B-062 | 2026-09-17 | A size claim the twin cannot check is refused rather than ignored. | The claim check skipped any dimension where the twin had no number, which is exactly the case where a claim is least supportable: the piece the twin refuses to measure. "Nothing to compare it against" was being treated as "nothing to object to". | Yes |
| B-063 | 2026-09-17 | Written instructions name the yarn on every row of a multi-colour pattern, and the reverse compiler checks it. | The whole catalogue's written instructions omitted colour: a two-colour mosaic was only workable from the chart. In overlay mosaic the colour *is* the motif, so a document that names the wrong yarn produces a different object, which makes colour a structural check rather than a presentational one. | Yes |
| B-064 | 2026-09-17 | How the rounds are worked is stated once per component and read back from the text. | Joining each round leaves a seam up the side; spiralling does not. A round-worked document that says neither is missing an instruction the maker needs, and one that says the opposite describes a different fabric. Stated once rather than repeated on sixty lines, so there is one source of truth to check. | No |
| B-065 | 2026-09-17 | The finishing is part of the CIR, and a flat panel may be called a basket only once something joins it. | Multi-piece patterns without assembly steps are a bag of rectangles and a wish. | B-066 | 2026-09-17 | The customer document carries its own version, and re-certification replaces the stored certificate. | The release hash is taken over the CIR *and* the written text, so a change to the writer invalidates every certificate issued before it -- while the PDF quietly regenerates from the new writer. | B-067 | 2026-09-17 | A product whose certificate is refused has its listing withdrawn. | Refusing a certificate and leaving the storefront untouched leaves a draft listing for a product the release chain has just rejected. The only thing between that draft and a customer was shadow mode, and shadow mode is a phase, not a guarantee. | No |
| B-068 | 2026-09-17 | Launch readiness separates blockers into build, integration and owner, and only the owner's reach the owner queue. | The directive forbids asking for an Etsy account, KYC or banking "because they will eventually be needed", and the honest test of that is whether the system can tell the difference between a requirement it has not met yet and one it cannot meet at all. | B-069 | 2026-09-17 | The owner queue is written by the system on a daily cadence, not by hand. | The table has had the directive's five columns -- action, reason, maximum cost, minutes, consequence of delay -- since the first build and nothing had ever written to them, because until the catalogue, imagery, pricing and copy existed every blocker was ours. | B-070 | 2026-09-17 | Idempotency keys for design-derived work carry the design's own fingerprint, and the rebuild compares the stored design against the one the code produces. | Found by watching production accept the round-worked rebuild and keep serving the old one. `cir.draft` was keyed `draft:{slug}` -- once per slug, forever -- so a re-engineered product could never enter the chain: the draft was done, the compile key was taken, certification never re-ran, and the `DOC_VERSION` bump meant to deliver the fix could not reach the stage it was bumped for. A slug and a version do not identify a design; the design's content hash does. | B-071 | 2026-09-17 | The post-certification chain is keyed on the certified release hash, and a listing records which release produced it. | Found in production ten minutes after B-070, which is the same bug one stage lower: certification re-ran, produced a new release hash, and then found `listing:{slug}:{version}:c{chain}` already taken by the previous rebuild, so the corrected design certified and the old listing stayed. | B-072 | 2026-09-17 | A rebuild's trigger is part of the idempotency key and rides the whole chain. | The third layer of one bug, each layer found by watching production refuse to change. A rebuild exists precisely for the case where the work already ran and its result is no longer right, so keying only on the product, the code version and the certified release still leaves every stage's key taken. The rebuild now mints a token from the transition it is correcting and passes it down the chain, so each stage re-runs once for that rebuild and not once per cadence. | Yes |
| B-073 | 2026-09-17 | The rebuild records why it judged each listing current or stale. | It reported "nothing to do" three times while two products sat visibly wrong in production, and from outside the process that claim was unfalsifiable. The audit entry now carries the comparison it made for every listing. | No |
| B-074 | 2026-09-17 | A physical sample calibrates the yarn estimate and falsifies the size claim, and those are kept separate. | Folding a size disagreement into a calibration factor would turn the one check that can catch a wrong geometry model into a number that silently absorbs it. So a yarn difference within a plausible band becomes a factor; a finished size outside 12% of the claim raises a defect against the product instead. The factor is keyed on the yarn and the stitch it was measured on -- a test caught an earlier version keying on weight alone, where "worsted cotton" and "worsted acrylic" collided. | Yes |
| B-075 | 2026-09-17 | The Etsy publishing path is written and unit-tested while it cannot publish. | It is the only code in the system that could reach a customer, and the alternative is writing it for the first time on the day it matters. Three refusals sit in front of every request, in this order: phase, then the owner's authority, then credentials -- so a misconfigured key can never be the reason we stopped, and a present key is never mistaken for permission. The transport is the only way out and the tests count its calls: in shadow, with credentials present, zero requests are made. | No |
| B-076 | 2026-09-17 | The client refuses a listing it cannot map rather than truncating it. | A title cut at Etsy's 140 characters mid-word is a listing nobody approved, published under a certificate that describes something else. The limits are Etsy's and the policy gate already enforces them upstream, so this check should never fire -- which is exactly why it is here. | No |
| B-077 | 2026-09-17 | "Listing created, file not attached" is reported as its own outcome. | A listing on Etsy with no digital file takes money and delivers nothing. It is neither a success nor a plain failure: the recovery is to complete or delete that listing, not to create another one. It also surfaces the dependency on object storage, because a process that renders a PDF, restarts, and then uploads has nothing to send. | No |

## Standing constraints carried from the spec

These are not re-decidable by a future session without the owner:

- Patterns are software releases. Never generate a beauty image and ask a model to guess the
  instructions (section 2).
- No fake reviews, buyers, favourites, sock-puppets, deceptive discounts or artificial
  engagement (Execution Directive, section 8).
- Never bypass CAPTCHA, KYC, identity checks or legal acceptance.
- Never copy competitor instructions, charts, photography or protected designs. Research is
  for demand and merchandising intelligence only.
- Never claim an integration, deployment, pattern, listing, test, campaign, customer or
  revenue exists until verified.
- Deterministic pattern validation wins even if every LLM disagrees (section 27).
