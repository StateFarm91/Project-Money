Authority: independent recommendation only. Claude/Opus remains the sole Build 2 integrator/certifier. Filling this template must not modify requirement status.

## Required chain

**Requirement → Producer → Durable evidence → Consumer → Decision → Protected action → Observable result → Independent proof**

For an internal-only requirement, name the real runtime effect instead of inventing an external action. For a gated requirement, prove the built half refuses honestly now and resumes when the real prerequisite arrives. No gate can hide unfinished software.

## Automatic rejection of false proof

A module/import, registered handler, cadence declaration, test filename, passing isolated helper, database row, produced report, owner card or enqueued job is insufficient alone. Follow it to the consuming decision and actual effect.

Reject unsupported upgrades of meaning: rarity→strength; swatch→finished object; seller country→buyer population; draft→published; plan→executed; eligibility→transition; hash syntax→bytes; rights label→permission; audit timestamp→fresh dataset; artifact presence→approval; missing evidence→recovery; assumed cost→measured profit.

A gate must block the final protected action and remain blocking after planning, retries, restarts and rebuilds. Unknown gate state is unknown, not verified closed or satisfied. Multiple independent holds must be preserved together.

## Gated built-half proof

1. Close the real prerequisite in a disposable test and exercise the normal producer/consumer path.
2. Verify explicit reason, no prohibited adapter call, durable pending state and no fabricated measured output.
3. Supply the prerequisite through its real supported producer or a clearly labelled external-boundary test adapter.
4. Verify normal scheduling resumes, downstream work consumes that evidence and all other gates remain binding.
5. Separate this mechanism proof from actual production capability, owner consent, data maturity or external benchmark success.

## Counterevidence and final audit

Record a disproved finding with exact reproducer and trace, not an assertion that tests are green. Retain failing tests until a valid repair or documented correction of the audit hypothesis is established. Review all 320 rows on the final integrated SHA; do not rerun the old 9434c53 audit as a substitute. Reconcile every actionable gap, valid gate and unresolved unknown before Opus considers certification.
