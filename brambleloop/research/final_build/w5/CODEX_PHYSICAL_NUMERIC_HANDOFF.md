# Physical sample numeric input validation

Based on the isolated Batch 6 safety preview `6cb70e3`. The actual `physical.record` handler converted boolean ball-band and yarn weights to floating point before checking the assessment. A synthetic sample using `ball_band_grams=True` and a matching metres-per-gram ratio was accepted and stored; the boolean became `1.0`. Other raw numeric report fields also allowed boolean values through the finite-number check.

The handler now rejects boolean mass/length values before conversion; the common physical assessment refuses boolean or nonnumeric reported measurements. Existing numeric conversion for ball-band and yarn weights remains. Synthetic tests exercise the real Worker and a valid numeric control; no actual physical test, tester authorization, or measurement was created. The independent reviewer ran the focused handler tests 7/7. Extremely large integer values can still fail closed by raising an overflow; this is an availability edge. Authentication of real testers and evidence, concurrent evidence fencing, and all existing Batch 6 review blockers remain unresolved. No PostgreSQL test, deployment or production activity is claimed.
