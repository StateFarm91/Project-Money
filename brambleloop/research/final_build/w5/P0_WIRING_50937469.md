## How the mechanics work (applies to every row)

- **Scheduler.**
  - `Worker.tick` (`runtime/worker.py:1244`) enqueues every `CADENCES` entry (`runtime/worker.py:604-1072`).
  - Each entry is enqueued with `idempotency_key = cadence:<name>:<window>` (`worker.py:~1283-1286`), so it is durable and runs without a Claude session.
- **Idempotency.**
  - `DurableQueue.enqueue` rejects any key that already exists, in any status, raising `DuplicateJob` (`queue/durable.py:247-275`).
  - Keys are therefore permanent, not only active-job dedupe. For example, `draft:<slug>` can be enqueued once ever.
- **Restart recovery.**
  - `claim` takes a RUNNING job whose lease has expired (`queue/durable.py:315-341`).
  - A job that is out of retries goes to DEAD (`queue/durable.py:398-425`).
  - Leases are renewed while the handler runs and capped at `MAX_HANDLER_SECONDS = 3600` (`worker.py:1078,1124`).
  - Completion is fenced to the lease holder (`worker.py:82-103`).
  - `ops.queue_check` re-drives defect dead letters once per deployed commit (`runtime/pipeline.py:2934-3001`).
  - `ops.thrash` breaks identical-call loops (`runtime/release.py:7585`).

## (3) What is already CONNECTED

These handoffs run from the worker with no Claude session:

- **Market research.** `radar.scan`, `culture.sweep`, `research.sweep` and `research.investigate` run on cadence.
- **Competitor monitoring.** The watchlist and MJ scans run with per-shop backoff. They produce coverage gaps and research tasks.
- **Main chain.** POOL score → `cir.draft` → `cir.compile` (one deterministic revise) → `gate.certify` → `listing.draft` → `assets.build` (PDF in US and UK, charts, disclosed renders, frame review) → `pricing.position` → `listing.seo` → `launch.plan` → `store.publish`, which is refused in SHADOW.
- **Every link above** is durable and idempotent (permanent keys) and handles failure with named refusals:
  - teardown and owner-veto withholding;
  - dead-end successors for pricing, assets and launch;
  - halt retry.
- **Imagery** auto-triggers from `assets.build`. It is spend-gated by the `image_generation` gate, the per-gallery `spend_plan` and the call cap. The gallery stops at owner review.
- **Listing package and owner review card.** A 6-hourly sweep.
- **Recovery.**
  - `chain.rebuild` and `release_recovery` (halted certifications, unseeded Launch-0) run hourly.
  - `chain.successors` runs hourly, once per commit.
  - Leases expire and are reclaimed with fencing.
  - Dead letters are re-driven per commit, and thrash detection is in place.
- **Commercial learning to radar.** `listing.outcomes` → `improve.commercial_lessons` → `radar.score` lesson nudge. It is wired, but has no input in SHADOW.
