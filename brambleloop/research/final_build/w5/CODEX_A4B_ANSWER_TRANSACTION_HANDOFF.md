# A4b transactional answer continuation

Based on `codex/a4b-enrichment-continuation` at `f19b878d4d38edc21f53d9a873d60ffcb9973bbc`. The queue savepoint implementation and its tests are copied from the previously reviewed `codex/jobqueue-savepoint-preview` commit `ee32f68f05ae0a697b37c52cbb76114694ab965f`; the integrator must preserve both sets of changes.

Adds a narrowly scoped `research.enrichment_answer` handler for already-authorized static seed payloads and changes the scheduled sweep to use the same serialized transaction as answering. The transaction rechecks request state; a real handler checks and locks the producer job and its inputs and lease; accepted responses atomically stage the draft job, causal link and ANSWERED audit. Unsuccessful responses atomically stage ANSWERED and, when still open, REQUESTED. If a concurrent response/sweep already changed the request, the losing handler returns a named changed result. Legacy direct callers without transactional adapters fail closed and must adopt the new interface. Research still needs a real authorized producer, and dynamic approvals remain explicitly held.
