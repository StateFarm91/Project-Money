## Method

The audit was read-only and was done before anything changed. It counted only links the code
wires, meaning links reachable from `app/runner.py` → `Scheduler.tick` / `Worker.run_once`. It
did not count links that only appear in docstrings. Wire-level integrity was checked
mechanically for every cadence: the agent exists, the agent is permitted the job type, the job
type is not structurally forbidden, and a handler is registered. **All 102 base cadences passed
that check.**

The defects are therefore not "a cadence points at nothing". They sit one level up, in the
loop the directive requires: **observe → determine work → prioritise → create missions →
execute → validate → hand off → follow-on → measure → persist lessons → repeat**.

For every department, the following links are the same:

- **Mission creation:** `autonomy.orchestrator._enqueue_mission` writes three things: a job with
  idempotency key `autonomy:<dept>:<evidence fingerprint>`, a `company_memory` row with
  kind=mission and its evidence sources, and a `company_timeline` row (mission.created).
- **Execution:** the ordinary worker, which goes through `Registry.authorize`.
- **Validation and measurement:** the next tick reconciles each mission against its job. The
  outcome is one of useful, noop or failed, and it is persisted.
- **Learning signal:** department KPIs (`autonomy.kpis`) are written by
  `autonomy.department_review` as kind=kpi_snapshot. A regression or a tripped guardrail
  becomes a routed `lessons` row.
- **Improvement path:** lessons → Learn's generator (`improve.mine` / `improve.retrospective`)
  → the existing improvement pipeline (sandbox, league, promotion monitor).
- **Next wake:** the earliest of the department's cadence windows and the next 15-minute
  orchestrator window. `status.summary` reports it.

## Broken links found (defects), and what happened to each

| ID | Severity | Link | Finding | Status |
|---|---|---|---|---|
| AM-01 | critical | work generation | Idle work was generated only company-wide. `swarm.orchestrate.feed_idle` fed the standing backlog only when **no** non-swarm job was open anywhere. With more than 100 cadences the queue is almost never empty, so a department with nothing to do was never given work. | **REPAIRED**: `autonomy.orchestrator.tick` detects idleness per department every 15 min (cadence `executive_orchestrator`). |
| AM-02 | high | work generation | `BACKLOG_JOBS` names standing work only for Intelligence, Platform/Executive and Learn. Seven departments had no idle work generator. | **REPAIRED**: all 11 departments have evidence-driven generators (`charters.generatable`, `generators`). |
| AM-03 | high | mission creation | A cadence job carries only `{"cadence": name}`. Why work was created, and from which evidence, was never persisted. | **REPAIRED**: a `company_memory` mission row with evidence and sources. |
| AM-04 | high | learning signal | There were no department KPIs with anti-gaming guardrails (F-918). `agent_quality` measures per-agent job success, which a no-op run satisfies. | **REPAIRED**: `autonomy.kpis` voids a reading when a guardrail trips. No-op runs count zero, duplicate outputs count once, generated no-op work counts zero, and UNKNOWN is never 0. |
| AM-05 | high | durable memory | There was no persistent company memory or company timeline (F-920, F-927). `audit_log` has no department, mission or outcome linkage. | **REPAIRED**: `company_memory` and `company_timeline`, both keyed and idempotent. |
| AM-06 | high | morning handoff | Nothing inside the runtime produced a morning brief (F-896). | **REPAIRED**: `autonomy.morning_handoff`, generated once a day after 11:00 UTC. |
| AM-07 | high | recovery fencing | Completion was fenced by worker **name** only, and the embedded runner named itself `web-<pid>`. Two containers in an overlapping deploy can share a PID, so a reclaimed job's stale attempt could complete over its successor. | **REPAIRED**: `jobs.lease_token` is set per claim (ported from Codex 8877f05) and checked on complete, fail and heartbeat. The hostname was also added to the default worker name. |
| AM-08 | medium | wake | An empty queue waited for the next cadence window. | **REPAIRED**: `Scheduler.tick` → `orchestrator.idle_wake`, keyed per 5 min. |
| AM-09 | medium | improvement path | Department outcomes reached Learn only as failures. A department whose useful output stopped produced no lesson. | **REPAIRED**: `department_review` routes lessons on regression or a tripped guardrail. Learn's generator consumes `lessons`. |
| AM-13 | medium | starvation | With one active pool worker, a CPU-bound render or planning cycle held the only claimer, and the orchestrator waited behind it. | **REPAIRED**: a dedicated control lane (`runtime/lanes.py`, ported and adapted from Codex) claims only orchestrator and liveness job types. |

## What "repaired" does and does not mean

- **Proven by test:** idle departments receive work from durable evidence. Blocked and failing
  departments are isolated. Protected work becomes one deduplicated owner action and never a
  job. A worker killed mid-job (SIGKILL) and then reclaimed leaves exactly the effects of one
  clean run. Same-named workers cannot complete each other's attempt. KPIs cannot be farmed.
  A simulated night (32 ticks, clock advanced) produces useful work in 10 of 11 departments
  with no spend and no protected job; the 11th was deliberately blocked.
- **Proven by runtime run:** the real embedded runner was run in-process in shadow phase, with
  no network and no credentials. See `evidence/A_runtime_proof.json` and `handoff_A.md`.
- **Not proven:** 24 h of hosted uptime. Production has not run this code; nothing was
  deployed.
- **Honest limitation:** once an idle department has done all the work its current evidence
  supports, it reports **SATURATED**. It does not invent work. It wakes again on new evidence,
  on an overdue cadence, or at its next self-review window (6 h). In the simulated night this
  was the commonest state between bursts. The scheduler's 103 cadences still run alongside
  the orchestrator in production; the simulation deliberately excluded them to isolate the
  orchestrator.
