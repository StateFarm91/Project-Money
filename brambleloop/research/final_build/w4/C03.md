Branch `claude/w4-C03`, cut from `origin/claude/w4-INTEG7` at 4d3d1ee8. The cluster is defined in
`CLUSTERS.md` on `claude/w4-FMBATCH2`, and its rows are F-699, F-705, F-707, F-505, F-126, F-412,
F-710, F-095 and F-097.

Every switch stays off. No model call, spend, Etsy write or deploy was made. Each new path that
would make a paid call is gated behind a switch that defaults to OFF:

- `BRAMBLELOOP_FAILOVER_DRILL`
- `BRAMBLELOOP_OUTCOME_ROUTING`
- `BRAMBLELOOP_CHALLENGER_RUNS`

These paths take their model `call` from the caller and never build a model client themselves.
`BRAMBLELOOP_LAURA_CEO_MODEL` and the other Laura switches are not touched.

Files touched:

- `improve/`: new `bounded.py`, `superseded.py`, `methods.py` and `challenger_runs.py`; edits to

## Rows

### F-705 Permanent Learning Loop: done

- **Gap:** most cells had no sandbox trial, so a proposal on them stayed PROPOSED for ever. The
  loop had a HYPOTHESIS step but no EXPERIMENT step.
- **Built:** `improve/bounded.py` registers the `bounded_experiment` trial in `runner.TRIALS`.
  - It applies to any cell. A proposal qualifies when it declares `scope.max_days`.
  - `bounded.start()` records who applied the change, what was applied and how to undo it, then
    opens the window. If no baseline was taken at proposal time, it takes one from the newest
    production reading before the change.
  - The trial runs only after the window closes. It reads only `improve.measure` production
    points inside the window and takes their mean. At least 2 points are required.
  - From there the existing runner takes over: regression and adversarial tests, approval by the
    evaluator, promotion gated by tier, and the monitor.
  - `bounded.coverage()` reads all eight stages for each department's cell from the registries.
- **Laura:** `laura/executive/loop.py` registers the provider `PROVIDERS["self_improvement"]`.
  - When an experiment window has closed without enough readings, the provider reads DEGRADED.
  - Laura then delegates `improve.measure` to Learn.
- **Tests:** in `tests/test_w4_c03_learning.py`:
  - `test_f705_every_department_cell_has_an_experiment_step_and_every_stage`
  - `test_f705_a_cx_experiment_runs_the_whole_loop_through_the_sandbox` (one proposal goes from
    proposed through start, readings, sandbox, both tests and approval to promoted)
  - `test_f705_a_baseline_is_taken_before_the_change_never_after`
  - `test_laura_turns_a_stalled_experiment_into_a_measurement_mission`
- **SHA:** 36a8c8d2, with the Laura provider in 3f244157.
- **Remaining acceptance:**
  - Departments have to call `bounded.start` when they apply real changes.
  - Adversarial validation is still deterministic: re-derivation, a governance re-check and a
    hidden-surface check. No model adversary is configured; that would be a paid model path.
  - Production evidence requires deploy plus real readings.

### F-412 Research-to-Experiment Bridge: done

- **Built:** `bounded.research_intake()`, which runs at step 0c of every `improve.sandbox` pass

### F-126 Superseded Evidence Retention: done

- **Built:** `improve/superseded.py`.
  - `supersede()` writes a marker that cannot be replaced or removed. The marker records the kind
    (`confounded`, `invalid` or `replaced`), the reason, who set it, when, and optionally
    `superseded_by` and the confounders.
  - The row is kept with its baseline and result. An open row is closed as REJECTED with the
    reason.
  - Superseded rows are left out of the aggregates:
    - `failure_memory._improvement_failures`: a confounded loss is not a disproof.
    - `director.experiments`: reported in a new `superseded` list instead of completed or killed.
    - `cells.retrospective`: reported in a new `experiments_superseded` field.
  - When the runner finds a confounded experiment window (another promotion, revert or concurrent
    experiment on the same cell), it supersedes the row automatically.
- **Test:**
  `test_f126_a_confounded_experiment_is_retained_superseded_with_reason_and_not_a_failure`.
- **SHA:** 36a8c8d2.
- **Remaining acceptance:** none on the engineering side. The earlier precedents (the image
  benchmark in 4766be8a and growth confounders) are unchanged.

### F-710 Outcome-Based Model Routing: done (switch-gated)

- **Built:** `routing.outcome_route()` ranks every league routing configuration for a task. A
  candidate routes only when all of these hold:
  - Its provider has a text adapter in `ROUTABLE_PROVIDERS`. That is Anthropic today, so another
    provider's model is recorded and never routed.
  - Its payload is current.
  - `league.compare` shows it beats the incumbent on recorded runs (quality, cost, latency,
    reliability and holdout).
  - The owner's decision is recorded.
  - For a gate task, the contract passes.
- **Ranking:** quality first, then cost, then latency.
- **Switch:** `effective_route` follows the ranking only when `BRAMBLELOOP_OUTCOME_ROUTING=1`. The
  ranking is re-derived on every read, so a later losing run reverses the route.
- **Tests:** in `tests/test_w4_c03_routing.py`:
  - `test_f710_routing_follows_demonstrated_outcomes_only_when_switched_on_and_approved`
  - `test_f710_a_gate_task_moves_only_to_a_model_whose_contract_passes`
  - `test_f710_a_model_the_gateway_cannot_call_is_recorded_never_routed`
- **SHA:** 41b383eb.
- **Remaining acceptance:**
  - An adapter for a second text provider (GPT, Codex or Fable) needs an owner-funded account.
  - Real league runs need challenger runs (see F-699).
  - The owner decides whether to turn the switch on.
