- **Retention guard fix:**
  - **Failure:** the first run of `test_w4_fmbatch1_retention_guard` failed.
  - **Cause:** the new state was stored as audit-log rows, and the code reads six of those
    actions back by name. `ops.retention` had no entry for those reads. It prunes `audit_log`,
    so this state could have been forgotten.
  - **Fix:** commit 9a0a5628 stores the state as `operating_readings` rows instead, which are
    never pruned.
  - **Why not the retention table:** `ops/` belongs to Workstream B, so I moved the store
    rather than editing it.
  - **Result:** the guard now passes 5/5 on this branch.
  - **Same problem elsewhere:** it also affected C03 (`improve.method_version`) and C12
    (`listing.learning_window`). Both are fixed the same way, in e5dc33ec and 58317cc3.
- **Fail-before:** checked against base 2aeb177f with `git grep`. `record_case`,
  `service_standards`, `open_change`, `cross_surface`, `discover`, `ui_drift`, `contract` and
  `launch/non_delay.py` are all absent there, so every new test fails on import.
