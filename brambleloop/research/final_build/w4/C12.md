### F-516@v0.16 Search Visibility Ingestion: built (6efad5bb)

### F-517@v0.16 Search Visibility Closure Proof: built (6efad5bb)

- **What was built:** clearing an item now records a `confirmation`:
  - the id of the reading that cleared it, and when that reading was taken;
  - hours from first seen to cleared;
  - hours from the remediation to cleared;
  - the reference of the remediation.
- **Severity changes:** if Etsy changes an item's severity on a re-check, that is logged as

- **Test:** `test_f517_only_a_later_recheck_resolves_and_records_time_to_clear_and_proof`.
- **Still needs:** real re-checks after go-live.

### F-560 Search Visibility Three-Area Model: built (6efad5bb)

- **What was built:** `areas()` reports Listings, Shop and Customer Service separately. Each is
  red, amber or green, with its first-party findings and timestamps.
- **No default green:** an area is UNMEASURED until a complete reading exists, and turns amber
  when the newest reading is more than 7 days old.
- **Test:** `test_f560_three_areas_are_independent_and_never_green_by_default`.
- **Still needs:** Etsy has no API for this page, so the area status is fed only by owner
  readings.

### F-561 Search Finding Aging: built (6efad5bb)

- **What was built:** `aging()` tracks how long each finding has been open.
  - After a fix, it asks for a re-read until one has happened.
  - If Etsy still lists the item more than 7 days after the fix, it opens one incident. This
    7-day refresh window is an assumption, labelled as one, because Etsy publishes none.
  - The incident resolves when Etsy clears the item.
- **Test:** `test_f561_aging_asks_for_a_recheck_then_alerts_past_the_refresh_window`.
- **Still needs:** a daily caller. It belongs in `runtime/storefront_watch.py` or another
  runtime cadence. The runtime is Workstream C's, so it was not edited here.

### F-034 New-Listing Learning Window: built (5fc8115d)

- **What was built:** three functions, `learning_window`, `due_captures` and `record_capture`.
  - The schedule only starts from a **verified** activation in the lifecycle trail.
  - Evidence is captured on days 0, 1, 3, 7 and 14. The 14-day boost length is labelled as an
    assumption.
  - Each capture is dated, and names its source and evidence.
  - A capture is refused before its due day, and for a listing that is not live.
  - Captures more than 2 days overdue are reported as missed.
- **Test:**
  `test_f034_a_verified_activation_schedules_the_window_and_captures_are_dated`.
- **Still needs:**
  - publication;
  - a runtime cadence or owner card that calls `due_captures`, which is runtime work outside
    this file set.

### F-554 Bulk Listing Operations Guard: built (5fc8115d)

- **What was built:** `bulk_plan` refuses Product Truth, safety and legal fields outright, and
  any field not on the allowed list. It then:
  - previews the diff;
  - proves the affected count against the count the caller expected;
  - runs invariants: the recency rule for each renewal, at most 13 tags, a positive price;
  - records a rollback snapshot;
  - audits the plan.
- **Before running:** `verify_plan` refuses a plan if the listings changed after the preview.
- **No executor exists, and none was added.**
- **Tests:**
  - `test_f554_protected_fields_are_never_bulk_edited`
  - `test_f554_a_plan_previews_counts_checks_and_carries_its_rollback`
- **Still needs:** any future bulk executor (in `integrations/etsy.py`) must call this guard.

### F-555 Renewal & Expiry Strategy: built (5fc8115d)

- **What was built:** `renewal_economics` returns RENEW, LET_EXPIRE or UNMEASURED.
  - It works from measured outcome periods against the modelled renewal fee.
  - A listing with fewer than 30 measured visits is UNMEASURED and is never auto-renewed.
  - How close expiry is never changes the decision.
  - Renewal itself still has to pass `renewal_decision`.
- **Test:** `test_f555_expiry_alone_never_renews_and_evidence_decides`.
- **Still needs:**
  - live outcomes;
  - a comparison of manual against automatic renewal, which needs listings that have been
    renewed both ways.

### F-551 Dashboard Task Harvester: built for the API-reachable half (d5a01e8f)

- **What was built:** `etsy_dashboard.harvest()`.
  - Open receipts and census renewal/expiry items become OwnerAction tasks, each with an owner,
    a deadline and the evidence row.
  - When the next harvest no longer sees an item, its task is closed SATISFIED, naming that
    harvest as closure proof.
  - Messages, top tasks, Shop Advisor, recent activity and reminders are listed as UNAVAILABLE,
    with the reason, never as "none".
- **Test:** `test_f551_reachable_items_become_tasks_and_close_only_with_proof`.
- **Still needs:**
  - live orders;
  - a runtime cadence to call the harvester (runtime is outside this file set);
  - an owner-recorded intake for the dashboard-only items.

### F-552 Dashboard KPI Snapshot: built (d5a01e8f)

- **What was built:** `kpi_snapshot()` persists one snapshot per call, with its date range and
  channel.
  - Orders and revenue are measured, from ingested receipts.
  - Views and visits are owner-recorded (with the date they were read) or UNKNOWN, never 0.
  - Each snapshot is labelled a quick signal, not a substitute for detailed Stats.
- **Test:** `test_f552_snapshot_is_measured_orders_and_unknown_views_until_read`.
- **Still needs:** real orders after go-live.

### F-562 Stats Traffic-Source Model: built (d5a01e8f)

- **What was built:** `record_traffic_sources()` parses the owner's Stats traffic-source export.
  - Etsy's labels are kept exactly as Etsy writes them, alongside Etsy's definitions.
  - An unrecognised label is kept as itself, never merged into "other".
  - Duplicate rows, rows that are not counts, and missing columns are refused.
- **Test:** `test_f562_sources_are_kept_separately_with_etsys_labels_and_definitions`.
- **Still needs:** the owner's exports.

### F-580 Apps Inventory & Permissions: built (d5a01e8f)

- **What was built:** `record_apps` and `apps_register`.
  - The register includes this company's own app, with the scopes it holds, the scopes it
    requested, its purpose, owner and revocation path.
  - A third-party app is only recorded when all of the following are given: scopes, purpose,
    owner, last use, data access, cost and revocation path.
  - Security debt is flagged for apps unused for more than 60 days or with unknown last use,
    and for any scope held but never requested.
- **Test:** `test_f580_every_app_is_accounted_for_and_unused_ones_are_debt`.
- **Still needs:** the owner's reading of the Apps page.

### F-583 Shared Access Governance: built (d5a01e8f)

- **What was built:** `record_shared_access` and `shared_access_register`.
  - Each member has a label, permissions, what they need access for, the grant date and last
    activity.
  - The least-privilege check flags any permission beyond what the member needs.
  - Members idle for more than 60 days are flagged.
  - Permissions outside Etsy's model are refused.
  - The owner is recorded as accountable.
- **Test:** `test_f583_shared_access_is_checked_for_least_privilege_and_activity`.
- **Still needs:** the owner's reading of the Shared Access page.

### F-588 Partners You Work With: built (d5a01e8f)

- **What was built:** `record_partners` and `partners_register`.
