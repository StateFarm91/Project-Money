# REDFIX-B — four failing suites on claude/rc2-fixes

Base: `origin/claude/rc2-fixes` @ `744a0fee`; fix commit `cd3ddfd6` on `eng/redfix-b`. Each suite was run on its own with
`SUITE_REGISTRY=0 SUITES=tests/<suite>.py JOBS=$(nproc) bash run_tests.sh` on Python 3.13 in a `.venv` built from
`requirements.lock` + `requirements-test.lock`. Failure output came from `eng/inventory-shard-2` and `-3`.

- **test_v11_autonomy_timeline** — FIXED, 6/6. Root cause: `autonomy.map.follow_on_edges` only counted `enqueue()` calls whose agent and job type were literal strings. `sale.pipeline` is enqueued as `SPL.AGENT, SPL.JOB_TYPE` (`runtime/sale_pipeline_ops.py`, `runtime/release.py`), so the map reported it as never woken even though it is wired. Fix: the scanner now resolves module-level string constants, both from the same file and from imported package modules. Runtime values are still never read. `autonomy_map.json` was regenerated: 23 more real edges, no new broken links, and `never_woken_job_types` is empty for every department.
- **test_w4_close6_hygiene** — FIXED, 3/3 (it also passes with `SHARD=3/4 CHECKPOINT=1` exported, which is how the shard reproduced the failure). Root cause: the sandbox harness `tests/test_run_tests_script._env` stripped the original runner knobs but not the W4-B1 ones. A nested sandbox `run_tests.sh` started inside a `CHECKPOINT=1 SHARD=3/4` run inherited `SHARD`, sharded its own one-suite list to nothing and exited 2 with empty stdout. Fix: add `CHECKPOINT`, `CHECKPOINT_TOOL`, `RESUME` and `SHARD` to `_KNOBS`. The same leak and fix applies to the copy of `_KNOBS` in `tests/test_w3_suite_job_identity.py`, which failed the same way in shard 3 and now passes 6/6. No assertion was changed. Dependents also pass: `test_run_tests_script` 11/11, `test_w3_tmp_hygiene` 16/16, `test_w4_fmbatch1_failclass` 3/3.
- **test_final_closure_matrix** — ENVIRONMENT, no code change, 12/12. Root cause: the clone was shallow, so the mapping commits the matrix cites (e.g. `019ebf0e…`, `1b21e81c…`) were absent and `git cat-file -e` failed. After `git fetch --deepen=400 origin claude/rc2-fixes` every cited commit resolves and the suite passes unchanged. A fresh shallow clone will fail this suite again: runners need history at least back to the cited commits.
- **test_w4_autonomy_idle_departments** — NOT FIXED, still 3 passing then abort at `test_a_wide_rebuild_fits_the_varchar_200_key_column`. Root cause: the test predates D-ENG-PUBLISH-UNHALT U2 (2026-11-21). U2 deliberately stops the rebuild graph from planning artefacts of the retired legacy-duplicate slugs (`products.launch0.LEGACY_DUPLICATES`). Two of the test's 14 fixture slugs are exactly those slugs (`hexie-coaster-set`, `market-basket-trio`), so 12 are enqueued, not 14. The code is right. The correct fix is to replace those two fixture slugs with two live products, which leaves the assertion as strong as before. But U2 is recorded as routine engineering, not an owner decision, so this lane's rules do not allow the test edit. **Needs a coordinator or owner ruling to permit the fixture-slug change.**
- **test_vacuity** — 8/8. Also passing, after the map change: `test_w3_reachability_dynamic` 3/3, `test_w4_f454_agents` 2/2, `test_motif_backlog` 26/26, `test_w4_credhealth` 13/13, `test_w4_c12_wiring` 4/4.
